# Система автоматического полива растений

## Описание проекта

Проект представляет собой систему автоматического полива и выращивания растений на базе Arduino Nano. Система обеспечивает автоматический контроль влажности почвы, температуры и влажности воздуха, управление освещением и поливом в соответствии с заданным циклом выращивания.

## Целевая платформа

- **Микроконтроллер**: Arduino Nano
- **Дисплей**: OLED 128x64 точек (SSD1306)
- **RTC**: DS1302 (часы реального времени)
- **Датчики**: 
  - Датчик влажности почвы (аналоговый, емкостный или резистивный)
  - Датчик температуры и влажности воздуха (DHT11/DHT22)
- **Управляемые устройства**:
  - Светодиодное освещение
  - Система полива (помпа)
  - Вентиляция (в перспективе)

## Архитектура проекта

### Принципы разработки

1. **FSM (Finite State Machine)** - все асинхронные процессы реализованы через конечные автоматы для исключения блокирующих задержек (`delay()`)
2. **Модульность** - код разбит на отдельные модули/библиотеки
3. **Оптимизация ресурсов** - особое внимание к компактности данных и оптимальности кода из-за ограниченных ресурсов Arduino Nano
4. **Сохранение настроек** - все настройки сохраняются в EEPROM
5. **Именование приватных членов** - все приватные переменные и методы классов начинаются с символа `_`

### Модули системы

#### 1. Датчик влажности почвы (`soil_sensor`)
- Поддержка аналоговых датчиков (емкостных и резистивных)
- Механизм калибровки (min/max значения)
- Поддержка прямой и обратной зависимости показаний от влажности:
  - Резистивные датчики: при повышении влажности сопротивление падает, показания возрастают
  - Емкостные датчики: при повышении влажности показания падают
- Периодический опрос датчика (по умолчанию каждые 10 минут)
- Управление питанием датчика для защиты от коррозии

#### 2. Датчик температуры и влажности воздуха (`air_sensor`)
- Работа с DHT11/DHT22
- Асинхронное чтение данных через FSM
- Защита критичных участков кода от прерываний

#### 3. Кнопки (`button`)
- Обработка нажатий с защитой от дребезга контактов
- Поддержка короткого и длинного нажатия

#### 4. Таймер системный (`timer`)
- Таймер на базе `millis()`
- Используется для внутренних задержек системы

#### 5. Таймер RTC (`timerRTC`)
- Таймер на базе часов реального времени DS1302
- Отсчет времени в секундах с момента начала цикла выращивания
- Используется только для точного отсчета времени, без привязки к календарю

## Функциональность

### Цикл выращивания

Цикл выращивания настраивается от 30 до 200 дней и включает четыре последовательных периода:
- **Проращивание** (`GerminationLengthDays`): 3-7 дней. Первый день освещается 1 час, остальные дни проходят в темноте.
- **Весна** (`SpringLengthDays`): длительность задаётся в сутках; продолжительность светового дня определяется настройкой `SpringDayHours` (19-22 часов).
- **Лето** (`SummerLengthDays`): длительность задаётся в сутках; продолжительность светового дня определяется настройкой `SummerDayHours` (15-18 часов).
- **Осень** (`AutumnLengthDays`): длительность задаётся в сутках; продолжительность светового дня определяется настройкой `AutumnDayHours` (8-14 часов). Значение может быть нулевым.

**Особенности цикла:**
- Суммарная длительность периодов проращивания, весны, лета и осени автоматически проверяется на соответствие диапазону 30-200 дней.
- После окончания цикла (`GrowingPeriod::Completed`) система отключает освещение и полив.
- Значение `CycleLengthDays` вычисляется динамически как сумма длительностей всех периодов.
- Настройки по умолчанию: проращивание 3 дня, весна 33 дня, лето 34 дня, осень 0 дней; световой день по умолчанию: весна 20 часов, лето 18 часов, осень 12 часов.
- Модуль `GrowingCycle` предоставляет актуальные значения текущего дня, часа и минуты внутри дня для других подсистем.

### Настраиваемые параметры

#### Системные настройки (сохраняются в EEPROM):
- Длительность периодов проращивания, весны, лета и осени (тип `uint8_t`; проращивание 3-7 дней, остальные периоды ≥0; по умолчанию: 3 / 33 / 34 / 0)
- Длительность светового дня весны/лета/осени (`SpringDayHours` 19-22, `SummerDayHours` 15-18, `AutumnDayHours` 8-14; по умолчанию: 20 / 18 / 12 часов)
- Производная настройка `CycleLengthDays` используется только как виртуальный ключ и вычисляется как сумма длительностей периодов; значение автоматически валидируется на диапазон 30-200 дней
- Калибровка датчика влажности почвы (min/max значения)
- Продолжительность полива (секунды, по умолчанию: 18 сек)
- Пауза между поливами (секунды, по умолчанию: 600 сек / 10 мин)
- Влажность почвы для начала полива (min, %, по умолчанию: 58%)
- Влажность почвы для прекращения полива (max, %, по умолчанию: 85%)
- Максимальное количество поливов в одном цикле (по умолчанию: 6)
- Влажность почвы в режиме тренировки (%, по умолчанию: 25%)
- Продолжительность цикла очистки (секунды, по умолчанию: 15 сек)
- Количество циклов очистки (по умолчанию: 10)
- Пауза между циклами очистки (секунды, по умолчанию: 60 сек / 1 мин)
- Период проверки датчиков (по умолчанию: 10 минут)

#### Параметры, изменяемые в процессе работы:
- Любые настраиваемые параметры могут быть изменены в процессе работы
- При изменении параметров необходимо обеспечить консистентность системы:
  - Текущий день цикла (можно установить любой день в пределах цикла, время суток сохраняется)
  - Продолжительность цикла (не меньше текущего дня цикла)
  - Настройки полива (min/max влажность) - min должен быть меньше max
  - Калибровка датчика - min и max не должны совпадать
  - Продолжительность периодов - сумма должна соответствовать продолжительности цикла

### Процессы системы

#### Автоматический полив

Алгоритм работы:
1. При достижении минимальной влажности почвы запускается цикл полива
2. Включается полив на заданную продолжительность
3. Выдерживается пауза между поливами
4. Измеряется влажность почвы
5. Если достигнуто максимальное количество поливов, а влажность не увеличилась более, чем на 2%:
   - Выводится предупреждение об отсутствии воды
   - Пользователь может отреагировать → переход к п.1
   - Если нет реакции → автоматический переход к п.1 через 1 сутки
6. Если влажность достигла максимума → цикл полива прекращается
7. Иначе → переход к п.2

#### Ручной полив
- Принудительный однократный полив заданной продолжительности

#### Режим тренировки
- Прекращение полива до достижения заданной влажности (по умолчанию 25%)
- После достижения влажности ожидание 1 сутки
- Сигнал пользователю о готовности к тренировке
- Если пользователь отреагировал → выход из режима тренировки
- Если нет реакции → автоматический выход через 1 сутки

#### Режим очистки
- Выполнение заданного количества циклов полива заданной продолжительности с заданным интервалом
- Возможность прекращения очистки нажатием кнопки

## Интерфейс пользователя

### Аппаратная компоновка
- **Экран**: OLED 128x64 точек
- **Кнопки**: 4 кнопки в ряд под экраном

### Основной экран

Отображает:
- Режим освещения (вкл/выкл, день/ночь)
- Температура воздуха
- Влажность почвы и воздуха
- Час цикла (время суток в рамках цикла)
- Время до следующей проверки датчиков (минуты)

### Функции кнопок в основном режиме

1. **Кнопка 1**: Вызов меню настроек
2. **Кнопка 2**: Принудительный полив
3. **Кнопка 3**: Немедленная проверка датчиков (сброс таймера ожидания)
4. **Кнопка 4**: Вкл/выкл дисплея

**Автоматическое выключение дисплея**: через 10 минут после последней активности пользователя (нажатия кнопки)

### Меню настроек

Меню поддерживает все описанные выше настройки системы. При проектировании и реализации меню будет создано отдельное детальное описание структуры меню и навигации.

## Управление внешними устройствами

### Выходные устройства:
- **Свет**: управление через цифровой пин (вкл/выкл) с поддержкой инверсии сигнала (`highIsOn`)
- **Полив**: управление через цифровой пин (вкл/выкл) с поддержкой инверсии сигнала (`highIsOn`)
- **Вентиляция**: управление через цифровой пин (вкл/выкл, в перспективе для опосредованного регулирования влажности и температуры воздуха)
- **Дисплей**: управление через библиотеку U8g2lib

## Технические детали

### Используемые библиотеки:
- `U8g2lib.h` - работа с OLED дисплеем SSD1306
- `Ds1302.h` - работа с часами реального времени DS1302
- `EEPROM.h` - сохранение настроек (встроенная библиотека Arduino)

### Пины Arduino Nano (конфигурация):
- **A0**: Аналоговый вход датчика влажности почвы
- **A1**: Управление питанием датчика влажности почвы
- **A2**: Датчик температуры и влажности воздуха
- **A3**: Управление светом (PIN_LIGHT)
- **A4**: Управление поливом (PIN_WATER)
- **A5**: Управление вентиляцией (PIN_VENTILATION, зарезервировано)
- **2**: Кнопка OK
- **3**: RTC DATA
- **4**: RTC CLK
- **5**: Кнопка UP
- **6**: Кнопка DOWN
- **7**: Кнопка CANCEL
- **8**: Дисплей RESET
- **9**: Дисплей DC
- **10**: Дисплей CS
- **11**: Дисплей DATA
- **12**: RTC ENA
- **13**: Дисплей CLK

- Логика полива
  - Описание: автоматический полив по алгоритму, обработка ошибок (отсутствие воды), ручной полив, управление помпой с учётом выбранной полярности сигнала

- Управление настройками и EEPROM
  - Описание: сохранение/загрузка настроек в EEPROM, проверка целостности данных, валидация параметров
  - Тестирование: тест-кейсы для проверки сохранения/загрузки, восстановления при повреждении данных, валидации

## Примечания

- Проект разрабатывается с учетом ограниченных ресурсов Arduino Nano
- Все асинхронные операции реализуются через FSM без использования `delay()`
- Настройки сохраняются в EEPROM с проверкой целостности данных
- В качестве референса используется версия 0.2.1.2 из папки `reference/`
- В перспективе планируется добавление управления вентиляцией для опосредованного регулирования влажности и температуры воздуха
- При изменении параметров в процессе работы необходимо обеспечивать консистентность системы (валидация взаимосвязанных параметров)
