# Модуль `Irrigation::Watering`

## Назначение

Модуль управляет автоматическим и ручным поливом, а также циклами очистки помпы посредством конечного автомата. Он разрабатывается по тем же принципам, что и `SoilSensor` и `AirSensor`: без использования `delay()`, с минимальным количеством переменных и с ориентацией на ограничения Arduino Nano.

## Зависимости и окружение

- `Timer` — локальные таймеры длительности полива, пауз между попытками, суточного тайм‑аута для ошибки «нет воды» и циклов очистки.
- `Settings::Manager` — источник всех параметров (пороги влажности, длительность попыток, паузы, количество циклов). Проверки корректности значений выполняются только в модуле настроек и НЕ дублируются в FSM.
- Любые уведомления пользователя (звуковые сигналы, индикация, логирование) реализуются во внешних модулях.

Модуль не взаимодействует с `TimerRTC`, `GrowingCycle` и `LightControl`.

## API

- `void begin(uint8_t pinPump, bool highIsOn = true)` — инициализация, перевод в состояние `Stopping`, настройка пина помпы. Параметр `highIsOn` задаёт активный уровень: `true` — HIGH включает помпу, `false` — LOW.
- `WateringState process(uint16_t soilMoisturePercent)` — основная функция, вызывается в цикле `loop()`, обновляет FSM и возвращает текущее состояние.
- `void setManualWatering()` — принудительный переход в режим ручного полива.
- `void setManualCleaning()` — принудительный переход в режим очистки помпы.
- `void setTraining()` — принудительный переход в режим тренировки растений.
- `void setIdle()` — принудительный переход в режим ожидания (`Idle`).
- `void stop()` — принудительный перевод в состояние `Stopping`, обнуляет текущие процессы.
- `WateringState getState()` — получить текущее состояние.
- Inline геттеры: `isPumpOn()` и, при необходимости, дополнительные компактные методы для тестирования (например, счётчик попыток).
- `uint32_t getRemainingSeconds()` — количество секунд до завершения текущего таймера состояний; при `Stopping` возвращает 0.

Все публичные методы статические, класс конструировать нельзя (конструктор удалён).

## Конечный автомат

Полное формальное описание состояний, переходов, используемых переменных и таблиц событий содержится в документе `../fsm_description.md`.

Основные состояния:

| Состояние | Назначение |
|-----------|------------|
| `Stopping` | Начальное состояние и принудительная остановка любых процессов. |
| `Idle` | Ожидание. При низкой влажности инициирует автоматический цикл. |
| `AutoPause` | Пауза между автоматическими попытками, анализ роста влажности. |
| `AutoWatering` | Активная попытка автоматического полива (помпа включена). |
| `ManualWatering` | Ручной режим, включение помпы по требованию пользователя. |
| `ManualCleaning` | Цикл очистки помпы (включение/пауза по настройкам). |
| `ManualPause` | Пауза между циклами очистки. |
| `TrainingWaiting` | Ожидание снижения влажности до уровня тренировки. |
| `TrainingReady` | Режим тренировки, ожидание действий пользователя (суточный таймер). |
| `OutOfWater` | Ошибка «нет воды», суточный таймер на автоматическое восстановление. |

### Ключевые правила

- Переходы между автоматическими состояниями происходят исключительно внутри `process`, на базе текущей влажности и таймеров.
- Ручной полив и очистка прерывают автоматический цикл, запоминая предыдущее состояние. Возврат к автоматике возможен после завершения ручного режима либо по команде `setIdle()`.
- Ошибка «нет воды» (`OutOfWater`) снимается автоматически через 24 часа переходом в `Idle`, либо внешними командами `stop`, `setManualWatering`, `setManualCleaning`.
- Режим тренировки запускается вызовом `setTraining()`; сначала FSM переходит в `TrainingWaiting`, затем при достижении `TrainingMoisturePercent` — в `TrainingReady`, где удерживается до истечения суточного таймера.
- Метод `stop()` всегда переводит FSM в `Stopping`, после чего требуется явный вызов метода, осуществляющего перевод FSM в другой режим, для возобновления работы.
- Управление пином помпы сконцентрировано в приватном методе `_setPump()`, который учитывает инверсию уровня, заданную при `begin()`.

## Тестирование

Для проверки модуля будет подготовлен скетч `watering_test.ino` с симуляцией сценариев:

- нормальный автоматический цикл с достижением требуемой влажности;
- исчерпание лимита попыток и переход в `OutOfWater`;
- ручной полив и очистка с прерыванием автоматического режима;
- автоматический выход из `OutOfWater` через сутки;
- режим тренировки: переход `TrainingWaiting → TrainingReady`, автоматический выход через сутки;
- корректная обработка команд `stop()`, `setIdle()`;
- подтверждение корректной работы помпы при активном HIGH и активном LOW.

Скетч использует моковые значения влажности и имитирует действия пользователя через Serial.
