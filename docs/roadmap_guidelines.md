# Рекомендации по структуре дорожных карт

1. **Группировка по этапам.** Объединяйте задачи, выполняемые в одной итерации, в общий этап с говорящим названием и списком целей.
2. **Нумерация задач.** Используйте составные номера вида `<номер этапа>.<номер задачи в этапе>` для всех задач, чтобы сохранялась возможность ссылаться на них из других документов.
3. **Чёткие заголовки.** Используйте структуру вида `## Этап N: Название` и детализируйте задачи подпунктом `### Задачи этапа`.
4. **Минимум лишнего текста.** В теле дорожной карты фиксируйте только сами задачи и необходимые зависимости; дополнительные принципы и детали выводите в отдельные документы.
5. **Актуализация зависимостей.** При изменении ключевых модулей включайте явный пункт анализа зависимостей, даже если в результате правки не требуются.
6. **Документация после тестов.** Переносите обновление проектной документации и рефакторинг вспомогательных артефактов (например, FSM-описаний) в самый последний этап после завершения тестирования.
7. **Связь с текущими модулями.** Явно отмечайте, какие модули должны быть адаптированы, и избегайте лишних действий для модулей, не зависящих от изменений.
8. **Отдельный файл для дорожной карты.** Храните каждую дорожную карту в отдельном `.md` файле, чтобы упростить отслеживание изменений и ссылок из других документов.
9. **Отслеживание прогресса.** Каждая задача должна начинаться с маркера `[ ]`, а после выполнения — с `[x]`, чтобы наглядно отмечать завершённые и активные пункты.
