# Архитектура с передачей указателя на SystemState

## Предложение

SystemController сохраняет данные о состоянии системы в структуре `SystemState` и передает указатель на эту структуру модулю Display при инициализации. Display использует заголовочный файл `system_state.h` для понимания структуры данных.

Это позволяет:
- ✅ Избежать дублирования данных (экономия памяти)
- ✅ Сохранить единый источник сведений о структуре данных (`SystemState`)
- ✅ Упростить архитектуру (нет промежуточных преобразований)

## Архитектура

```
SystemController (главный процессор)
    ↓ (циклический опрос модулей)
SystemState (структура данных состояния)
    ↓ (указатель передается при инициализации)
Display (инструмент для SystemController)
    ↓ (использует system_state.h для понимания структуры)
Отрисовка экрана
```

## Роли модулей

### SystemController
- Главный процессор системы
- Осуществляет циклический опрос всех модулей
- Получает данные о состоянии системы от датчиков и конечных автоматов
- На основании полученных данных принимает решения по управлению системой
- Сохраняет данные в структуре `SystemState`
- Передает указатель на `SystemState` модулю Display при инициализации

### SystemState
- Единый источник сведений о структуре данных, описывающих состояние системы
- Используется `SystemController` для хранения данных о состоянии системы
- Используется `Display` для понимания структуры данных, переданных через указатель
- Определена в заголовочном файле `system_state.h`

### Display
- Инструмент для SystemController
- При инициализации получает указатель на `SystemState` от SystemController
- Использует заголовочный файл `system_state.h` для понимания структуры данных
- Читает данные напрямую из `SystemState` через указатель
- Выполняет полную перерисовку экрана при каждом `update()`

## Реализация

### 1. SystemController

```cpp
// system_controller.h
class SystemController {
public:
    /**
     * Возвращает указатель на структуру данных состояния системы.
     * 
     * Используется для передачи указателя модулю Display при инициализации.
     * Display использует заголовочный файл system_state.h для понимания структуры.
     * 
     * @return const указатель на SystemState (не копируется)
     */
    static const SystemState* getSystemState();
    
private:
    static SystemState _state;
    static void _aggregateState();  // Агрегация данных в _state
};
```

### 2. Display

```cpp
// main_screen.h
#include "../irrigation/system_state.h"

class MainScreen {
public:
    /**
     * Инициализирует экран.
     * 
     * @param display ссылка на инициализированный объект U8g2.
     * @param refreshTimer внешний таймер, управляющий частотой update().
     * @param systemState указатель на структуру данных состояния системы.
     *                    Передается SystemController при инициализации.
     *                    Display использует system_state.h для понимания структуры.
     */
    static void begin(U8G2& display, Timer& refreshTimer, 
                     const Irrigation::SystemState* systemState);
    
    /**
     * Нужно вызывать в цикле. Метод проверяет таймер,
     * читает данные из переданного указателя SystemState
     * и выполняет полную перерисовку экрана.
     */
    static void update();
    
private:
    static const Irrigation::SystemState* _systemState;  // Указатель, переданный при инициализации
};
```

### 3. Пример использования

```cpp
void setup() {
    // ... инициализация других модулей ...
    
    SystemController::begin(/* параметры */);
    
    // Получаем указатель на состояние системы
    const Irrigation::SystemState* systemState = 
        SystemController::getSystemState();
    
    // Передаем указатель при инициализации Display (один раз)
    Display::MainScreen::begin(display, refreshTimer, systemState);
}

void loop() {
    // Обработка всех FSM, агрегация состояния системы
    SystemController::process();
    
    // Display читает данные через указатель и выполняет полную перерисовку
    Display::MainScreen::update();
}
```

## Преимущества подхода

1. **Экономия памяти:**
   - Нет копирования данных (указатель)
   - Нет промежуточных структур данных
   - **Итого: максимальная экономия памяти**

2. **Экономия CPU:**
   - Нет преобразований данных
   - Нет вызовов множества геттеров
   - Прямой доступ к данным

3. **Единый источник сведений:**
   - `SystemState` определяет структуру данных для всей системы
   - Изменение структуры требует изменения только `SystemState` и `Display`
   - Нет дублирования определений структур

4. **Простота:**
   - Один метод `getSystemState()` для получения указателя
   - Display сам решает, как отображать данные
   - Меньше кода в SystemController

5. **Чистое разделение ответственности:**
   - SystemController — управление системой и агрегация данных
   - Display — инструмент для отображения состояния
   - SystemState — единый источник сведений о структуре данных

## Недостатки

1. **Полная перерисовка:**
   - При каждом `update()` перерисовываются все блоки
   - Может быть избыточно, но упрощает код
   - Если производительность станет проблемой, можно добавить простую проверку изменений

2. **Зависимость от SystemState:**
   - Изменение `SystemState` требует изменения `Display`
   - Но это нормально, т.к. `SystemState` - это единый источник сведений о структуре данных

## Рекомендация

✅ **Рекомендуется реализовать этот подход**:
- Простота реализации
- Данные всегда актуальны
- Максимальная экономия памяти и CPU
- Единый источник сведений о структуре данных

## Миграция

1. Убрать все промежуточные структуры (MainScreenState, MainScreenAlerts, и т.д.)
2. Убрать все преобразования данных из SystemController
3. Display использует SystemState напрямую
4. Display включает `system_state.h` для понимания структуры
5. SystemController передает указатель на SystemState при инициализации Display
