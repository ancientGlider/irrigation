# План оптимизации проекта Irrigation

## Текущая ситуация

- **Целевая платформа:** Arduino Nano (ATmega328P)
- **Доступная Flash-память:** 30,720 байт
- **Текущий размер скетча (menu_test):** 31,384 байт
- **Переполнение:** ~664 байт (2.2%)

При сборке полного проекта переполнение будет значительно больше, так как добавятся:
- SystemController (полная инициализация)
- Датчики (SoilSensor, AirSensor)
- RTC и другие модули

**Оценка полного проекта:** ~35-40 KB → переполнение ~5-10 KB

---

## Анализ потребителей Flash-памяти

### 1. Шрифты U8g2 (главный потребитель)

| Шрифт | Где используется | Размер (оценка) |
|-------|------------------|-----------------|
| `u8g2_font_5x8_t_cyrillic` | MainScreen | ~4-5 KB |
| `u8g2_font_6x13_t_cyrillic` | MainScreen (заголовки) | ~6-8 KB |
| `u8g2_font_6x10_tr` | Menu | ~1 KB |
| `u8g2_font_10x20_tr` | Menu (крупные числа) | ~2 KB |
| `u8g2_font_5x7_tr` | Menu (мелкий текст) | ~0.5 KB |
| **Итого** | | **~13-16 KB** |

Шрифты с `_cyrillic` содержат ВСЕ символы Unicode, включая латиницу, кириллицу и спецсимволы — это избыточно.

### 2. Serial.print (отладка)

| Файл | Количество вызовов |
|------|-------------------|
| `irrigation.ino` | 30 |
| `main_screen.cpp` | 6 (под `#ifdef`) |

**Оценка:** ~500-1000 байт (строки + код Serial)

### 3. Код модулей

- Settings: ~2 KB (много switch-case)
- SystemController: ~1.5 KB
- Menu: ~3 KB
- MainScreen: ~2.5 KB
- Прочие модули: ~5 KB

## Анализ используемых символов

### Кириллица (из menu_strings.h и main_screen_labels.h)

**Заглавные (21 символ):**
```
А Б В Д Е Ж И К Л М Н О П Р С Т У Ц Ч Ь Ы
```

**Строчные (25 символов):**
```
а б в д е ж з и к л м н о п р с т у х ц ч щ ь ы я
```

**ASCII (используются везде):**
```
0-9: цифры
A-Z: латиница (в меню для технических значений)
.:;%°<>!? и другие спецсимволы
```

### Размер кастомных bitmap-шрифтов

При размере 5×8 пикселей:
- 1 символ = 5 байт данных + ~2 байта метаданных = ~7 байт
- 46 кириллических символов = ~320 байт
- 62 ASCII символов (цифры + латиница) = ~430 байт
- **Итого для 5×8:** ~750 байт

При размере 6×13 пикселей (если нужен):
- 1 символ = 13 байт + 2 байта метаданных = ~15 байт
- 46 кириллических = ~690 байт
- **Итого для 6×13:** ~1.5 KB

**Сравнение:**
- Полные U8g2 шрифты с кириллицей: ~10-13 KB
- Кастомные bitmap только нужных символов: ~2-3 KB
- **Экономия: ~8-10 KB**

## План оптимизации

### Этап 1: Удаление отладочного вывода

**Цель:** Освободить ~500-1000 байт

**Действия:**
1. В `irrigation.ino`:
   - Обернуть все `Serial.print` в `#ifdef DEBUG_SERIAL`
   - Или полностью удалить для production-сборки
2. Убедиться, что `SERIAL_DEBUG` не определён в `main_screen.cpp`

**Файлы для изменения:**
- `irrigation.ino`

**Оценка экономии:** ~500-800 байт

---

### Этап 2: Создание кастомной системы шрифтов

**Цель:** Заменить тяжёлые U8g2-шрифты на bitmap только нужных символов

**Архитектура:**

```
src/display/
├── custom_font.h          # Структуры и API
├── custom_font_data.h     # Bitmap-данные символов (PROGMEM)
└── custom_font.cpp        # Функции отрисовки
```

**Структура данных:**

```cpp
// custom_font.h
struct GlyphData {
    uint8_t width;           // Ширина глифа
    uint8_t height;          // Высота глифа  
    const uint8_t* bitmap;   // Указатель на bitmap в PROGMEM
};

// Таблица символов: код UTF-8 → индекс в массиве глифов
// Для кириллицы: 0xD0 0x90 (А) ... 0xD1 0x8F (я)
```

**Действия:**
1. Создать скрипт `tools/display/generate_custom_font.py`:
   - Вход: список нужных символов + TTF-шрифт или U8g2-шрифт
   - Выход: `custom_font_data.h` с bitmap в PROGMEM
2. Создать `custom_font.h` с API:
   - `void drawChar(U8G2& display, int16_t x, int16_t y, uint16_t codepoint)`
   - `void drawString(U8G2& display, int16_t x, int16_t y, const char* str)`
   - `void drawStringP(U8G2& display, int16_t x, int16_t y, const char* strP)` — для PROGMEM строк
   - `uint8_t getStringWidth(const char* str)`
3. Создать два набора глифов:
   - `FONT_SMALL` (5×8) — основной текст
   - `FONT_LARGE` (10×20) — для крупных чисел в меню (опционально)

**Файлы для создания:**
- `tools/display/generate_custom_font.py`
- `src/display/custom_font.h`
- `src/display/custom_font_data.h`
- `src/display/custom_font.cpp`

**Файлы для изменения:**
- `src/display/main_screen_fonts.h` — использовать кастомные функции
- `src/display/main_screen.cpp` — адаптировать вызовы
- `src/menu/menu_render.cpp` — адаптировать вызовы

**Оценка экономии:** ~8-10 KB

---

### Этап 3: Унификация шрифтов в меню

**Цель:** Использовать один размер шрифта вместо трёх

**Текущее состояние:**
- `u8g2_font_6x10_tr` — основной текст меню
- `u8g2_font_10x20_tr` — крупные числа при редактировании
- `u8g2_font_5x7_tr` — мелкий текст (min/max)

**Решение:**
- Использовать один шрифт 6×10 везде
- Крупные числа рисовать тем же шрифтом (или вообще отказаться от крупного отображения)
- min/max отображать тем же шрифтом

**Альтернатива:** Если кастомные bitmap реализованы, использовать их и для меню.

**Файлы для изменения:**
- `src/menu/menu_render.cpp`

**Оценка экономии:** ~2-3 KB (если не делать Этап 2)

---

### Этап 4: Оптимизация кода Settings

**Цель:** Уменьшить размер switch-case конструкций

**Текущая проблема:** В `settings.cpp` есть три больших switch-case:
- `_validateValue()` — ~150 строк
- `get()` — ~35 строк  
- `set()` — ~75 строк

**Решение:** Использовать таблицу дескрипторов вместо switch-case:

```cpp
struct ParamMeta {
    uint8_t offset;      // Смещение в структуре Data
    uint8_t size;        // Размер (1, 2 или 4 байта)
    uint16_t minValue;   // Минимум
    uint16_t maxValue;   // Максимум
};

const ParamMeta PARAM_META[] PROGMEM = {
    // ...
};
```

**Файлы для изменения:**
- `src/settings/settings.cpp`
- `src/settings/settings.h` (возможно)

**Оценка экономии:** ~500-1000 байт

**Приоритет:** Низкий (сложная рефакторинг)

## Риски и альтернативы

### Риск: Кастомные шрифты не дадут ожидаемой экономии

**Митигация:** Перед полной реализацией создать прототип с 5-10 символами и измерить реальную экономию.

### Риск: Кастомные шрифты ухудшат качество отображения

**Митигация:** Использовать bitmap из тех же U8g2 шрифтов (извлечь нужные глифы).

### Альтернатива: Переход на другую плату

Если оптимизация недостаточна:
- **Arduino Nano Every** — 48 KB Flash, pin-compatible
- **ESP8266** — 4 MB Flash (требует адаптации кода)
- **ESP32** — 4 MB Flash + WiFi (требует адаптации)

## Примечания

### О PROGMEM

> Пользователь спрашивал: "можно ли часть данных убрать из PROGMEM?"

**Ответ:** Нет, это **ухудшит** ситуацию. PROGMEM хранит данные во **Flash**, а не в RAM. Если убрать PROGMEM:
- Данные будут копироваться в RAM при старте
- RAM всего 2 KB — быстро закончится
- Flash-использование не изменится

PROGMEM — это **уже оптимизация**. Всё правильно используется.

### О компиляторных флагах

Arduino IDE уже использует оптимальные флаги:
- `-Os` — оптимизация по размеру
- `-ffunction-sections -fdata-sections` — удаление неиспользуемых секций
- `-Wl,--gc-sections` — сборка мусора линкером

Дополнительные флаги вряд ли помогут.
