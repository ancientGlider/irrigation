# Принципы оптимизации кода для Arduino Nano

## Общие принципы

При разработке модулей для Arduino Nano необходимо учитывать ограниченные ресурсы:
- **RAM**: 2 КБ (2048 байт)
- **Flash**: 32 КБ (32768 байт)
- **EEPROM**: 1 КБ (1024 байт)

## Правила оптимизации

### 1. Минимизация использования переменных

**Избегать:**
- Промежуточных переменных, которые используются только один раз
- Сохранения значений, которые можно получить напрямую
- Локальных переменных, которые не улучшают читаемость

**Пример плохого кода:**
```cpp
bool Timer::isReady() {
    unsigned long elapsed = getTime();  // Избыточная переменная
    if (elapsed >= _period) {
        return true;
    }
    return false;
}
```

**Пример хорошего кода:**
```cpp
bool Timer::isReady() {
    if (getTime() >= _period) {  // Прямой вызов
        return true;
    }
    return false;
}
```

### 2. Использование inline методов

Применять `inline` для:
- Простых методов-геттеров (1-2 строки)
- Методов, которые вызываются часто
- Методов, которые не содержат сложной логики

**Не применять `inline` для:**
- Методов с циклом или рекурсией
- Методов с большим количеством кода
- Виртуальных методов

### 3. Оптимизация типов данных

- Использовать минимально необходимый размер типа данных
- `uint8_t` вместо `int` для значений 0-255
- `uint16_t` вместо `unsigned long` для значений до 65535
- Избегать `float` и `double` где возможно (использовать целочисленную арифметику)

### 4. Принцип DRY (Don't Repeat Yourself)

- Переиспользовать существующие методы вместо дублирования кода
- Вызывать методы вместо копирования их реализации
- Использовать общие функции для повторяющихся операций

### 5. Оптимизация памяти

- Использовать `const` для константных данных (хранятся в Flash, а не в RAM)
- Использовать `PROGMEM` для больших массивов констант
- Избегать динамического выделения памяти (`new`/`delete`)
- Минимизировать использование строковых литералов

### 6. Оптимизация циклов

- Избегать вложенных циклов где возможно
- Использовать `break` и `continue` для раннего выхода
- Минимизировать вычисления внутри циклов

### 7. Оптимизация условий

- Использовать короткие условия для раннего выхода
- Избегать избыточных проверок
- Использовать `const` для константных выражений в условиях

### 8. Serial выводы для отладки

- **Использовать только английский язык** в Serial выводах (`Serial.print`, `Serial.println`)
- Кириллица может вызывать проблемы с кодировкой и отображением в Serial Monitor
- Английский язык обеспечивает корректную отладку на любых системах
- Это правило применяется ко всему проекту без исключений

## Примеры оптимизации

### Пример 1: Убрать промежуточную переменную

**До:**
```cpp
void process() {
    int value = calculate();
    if (value > 10) {
        doSomething(value);
    }
}
```

**После:**
```cpp
void process() {
    if (calculate() > 10) {
        doSomething(calculate());  // Если calculate() вызывается только здесь
    }
}
```

**Но:** Если `calculate()` вызывается несколько раз и имеет побочные эффекты или дорогая операция, лучше сохранить в переменную.

### Пример 2: Использование правильных типов

**До:**
```cpp
int counter = 0;  // int занимает 2 байта, но может быть отрицательным
for (int i = 0; i < 100; i++) {
    counter++;
}
```

**После:**
```cpp
uint8_t counter = 0;  // uint8_t занимает 1 байт, достаточно для 0-255
for (uint8_t i = 0; i < 100; i++) {
    counter++;
}
```

### Пример 3: Использование const

**До:**
```cpp
char message[] = "Hello";  // Хранится в RAM
```

**После:**
```cpp
const char message[] PROGMEM = "Hello";  // Хранится в Flash
```

## Примечания

- Оптимизация не должна ухудшать читаемость кода критически
- Сначала пишем читаемый код, затем оптимизируем
- Измеряем использование памяти при необходимости
- Документируем неочевидные оптимизации
