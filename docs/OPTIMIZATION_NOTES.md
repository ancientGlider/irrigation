# Заметки по оптимизации для микроконтроллера

## Вопрос 1: Хранение параметров инициализации

### Проблема
Необходимо исключить хранение в `SystemController` параметров, которые передаются в соответствующие классы однократно и не используются в системе нигде, кроме классов назначения (например, пины для помпы, света, датчиков).

### Решение
Параметры передаются напрямую в `begin()` соответствующих модулей и **не хранятся** в `SystemController`:

```cpp
void SystemController::begin(...) {
    // Параметры передаются напрямую, не сохраняются
    LightControl::begin(pinLight, lightHighIsOn);
    Watering::begin(pinPump, pumpHighIsOn);
    _soilSensor = new SoilSensor(pinSoilSensor, pinSoilVCC, checkPeriod);
    // ...
}
```

**Преимущества:**
- Экономия памяти (не храним неиспользуемые данные)
- Чистая архитектура (каждый модуль хранит свои параметры)
- Простота кода (меньше переменных)

## Вопрос 2: Оптимизация передачи данных в дисплей

### Проблема
Передача всей структуры `MainScreenState` в дисплей при каждом обновлении неэффективна для микроконтроллера, так как:
- Часто меняются только отдельные параметры
- Копирование всей структуры (~20+ байт) занимает время и память
- Сравнение всех полей для определения изменений также затратно

### Решение: Дифференциальное обновление с dirty flags

#### Архитектура

1. **Dirty flags в `SystemController`**:
   ```cpp
   struct DirtyFlags {
       bool header : 1;        // Режим, свет, время, предупреждения
       bool watering : 1;      // Состояние полива
       bool telemetry : 1;     // Данные датчиков
       bool cycle : 1;         // Цикл выращивания
   };
   ```
   Всего **4 бита** (1 байт) вместо копирования всей структуры.

2. **Сравнение изменений**:
   ```cpp
   void _checkChanges() {
       // Сравниваем только критичные поля
       if (_state.lightOn != _previousState.lightOn || ...) {
           _dirtyFlags.header = true;
       }
       // ...
   }
   ```

3. **Дифференциальная передача в дисплей**:
   ```cpp
   void _pushToDisplay() {
       if (_dirtyFlags.header) {
           Display::MainScreen::updateHeader(...);
       }
       if (_dirtyFlags.watering) {
           Display::MainScreen::updateWatering(...);
       }
       // ...
   }
   ```

4. **API дисплея для блоков**:
   ```cpp
   static void updateHeader(bool lightOn, uint8_t hour, uint8_t minute, 
                           const MainScreenAlerts& alerts);
   static void updateWatering(WateringViewState state, uint16_t remainingSeconds);
   static void updateTelemetry(const MainScreenTelemetry& telemetry);
   static void updateCycle(const MainScreenCycle& cycle);
   ```

#### Преимущества

1. **Экономия памяти**:
   - Dirty flags: **1 байт** вместо копирования всей структуры (~20+ байт)
   - Передаём только изменённые блоки (минимальные структуры)

2. **Экономия CPU**:
   - Сравнение только критичных полей (не все поля структуры)
   - Передача только изменённых данных
   - Меньше операций копирования

3. **Гибкость**:
   - Можно обновлять отдельные блоки независимо
   - Легко добавить новые блоки
   - Проще отлаживать (видно, что именно изменилось)

#### Использование

```cpp
void loop() {
    // Обработка всех FSM
    Irrigation::SystemController::process();
    
    // Обновление дисплея (только изменённые блоки)
    if (displayRefreshTimer.isReady()) {
        Irrigation::SystemController::updateDisplay();
        Display::MainScreen::update();
    }
}
```

#### Оценка экономии

**Было (передача всей структуры):**
- Копирование `MainScreenState`: ~20 байт
- Сравнение всех полей: ~10-15 сравнений
- Передача всех данных: всегда

**Стало (дифференциальное обновление):**
- Dirty flags: 1 байт
- Сравнение критичных полей: ~5-8 сравнений
- Передача только изменённых блоков: только при изменениях

**Экономия:**
- Память: ~19 байт на каждом обновлении (если ничего не изменилось)
- CPU: ~50-70% меньше операций сравнения и копирования
- Гибкость: можно обновлять только нужные блоки

## Рекомендации

1. **Всегда используйте `updateDisplay()`** вместо `getDisplayState()` + `setState()`
2. **Модуль дисплея** должен реализовать методы обновления блоков для поддержки дифференциального обновления
3. **При полном обновлении** (например, после возврата из меню) используйте `requestFullRefresh()`, который установит все dirty flags
