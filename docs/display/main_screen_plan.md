# План разработки модуля главного экрана

## Контекст

Модуль `Display::MainScreen` является инструментом для `SystemController`. При инициализации получает указатель на `SystemState` и использует заголовочный файл `system_state.h` для понимания структуры данных. Внешний вид экрана соответствует демо `tools/display/main_screen_server.py`.

## Принципы разработки

1. **Архитектура**: Работа через указатель на `SystemState`, без промежуточных структур данных
2. **Оптимизация памяти**:
   - Переиспользование лейблов (общие строки из единого источника `main_screen_labels.h`)
   - Побитовое хранение иконок в PROGMEM (1 бит на пиксель, не 1 байт)
   - Все строки и иконки в PROGMEM
3. **Тестирование**: Отрисовка на моковых данных, покрытие тестами
4. **Внешний вид**: Точно соответствует демо `main_screen_server.py`

## Примечания

1. **Побитовое хранение иконок**: Иконки из JSON конвертируются в массив `uint8_t`, где каждый байт содержит 8 пикселей (MSB = левый пиксель). Это экономит память в 8 раз по сравнению с побайтовым хранением.

2. **Переиспользование лейблов**: Строки "ВЕСНА", "ЛЕТО", "ОСЕНЬ" используются и для режима системы, и для сезона. Они хранятся один раз в `LABELS` и переиспользуются через индексы.

3. **Моковые данные**: Для тестирования создаются моковые структуры `SystemState` с различными значениями, что позволяет тестировать отрисовку без реального оборудования.

4. **Page buffer режим**: U8g2 используется в режиме page buffer для экономии памяти. Каждая страница отрисовывается отдельно в цикле `firstPage()...nextPage()`.
